# 智能文旅策划 Agent 项目架构可视化 HTML 设计规格

- 日期：2026-08-25
- 状态：已获用户批准，待实现
- 目标文件：`docs/project-architecture.html`

## 1. 目标与范围

生成一个可离线打开的单页 HTML，用于向开发者、评审者和后续维护者说明当前项目的真实架构、核心实现流程和韧性机制。文档以仓库当前代码与 README 为事实来源，不把规划中的生产化能力描述为已实现能力。

本次包含：

- 系统总体架构图；
- 旅行规划请求的端到端实现流程图；
- 文档上传、解析、向量化与检索流程图；
- 外部服务缓存、重试、熔断、恢复与降级流程图；
- Agent 状态与顶层状态判断矩阵；
- 安全边界、非交易边界和当前已知限制说明。

本次不包含：

- 修改业务代码或 API 合同；
- 接入 Mermaid、CDN 或其他运行时外部依赖；
- 将页面做成业务操作台；
- 伪造运行指标、健康状态或供应商数据。

## 2. 页面结构

页面采用单页纵向结构，包含固定侧栏目录和主内容区：

1. 项目总览：项目定位、MVP 边界和关键模块摘要；
2. 总体架构：浏览器、FastAPI、编排器、Agent、数据合同、外部服务和横切韧性能力；
3. 旅行规划流程：表单、校验、追踪标识、五阶段编排、受控失败、汇总和前端展示；
4. 文档处理流程：上传校验、文本提取、分块、Embedding、Chroma 和检索边界；
5. 熔断流程：缓存命中、请求分类、重试、失败阈值、打开状态、探测恢复和降级；
6. 状态判断：`success`、`partial`、`degraded`、`failed` 的数据合同和顶层状态规则；
7. 安全与限制：密钥、固定域名、响应脱敏、字段禁入、XSS 防护及生产化缺口。

每个图形区同时提供结构化文字说明，避免仅依靠颜色或图形传达信息。

## 3. 图形实现

- 架构图、流程图和状态图使用内联 SVG 绘制；
- SVG 使用清晰的节点标题、连线方向、条件标签和图例；
- SVG 外层容器允许横向滚动，页面主体不产生横向溢出；
- 关键状态使用颜色加文字标签双重表达：绿色表示成功、琥珀色表示降级/部分、红色表示失败、蓝色表示控制流；
- 图形尺寸使用 `viewBox` 与相对容器适配桌面和窄屏；
- 不使用外部图片、远程字体、CDN 脚本或网络请求。

## 4. 交互与可访问性

仅使用少量原生 JavaScript：

- 侧栏目录点击定位到章节；
- 主题切换按钮在浅色/深色之间切换，并通过 `localStorage` 保存用户偏好；
- 图中复杂节点可通过 HTML 说明卡片阅读，不依赖悬浮才能获得信息；
- 使用语义标题、`aria-label`、可见焦点样式和足够的文字对比度；
- `prefers-reduced-motion` 下关闭非必要动画；
- 无障碍阅读顺序与视觉顺序保持一致。

## 5. 事实与边界表达

页面明确区分“当前已实现”和“生产化后续”：

- 已实现：FastAPI 同源页面、顺序 Agent 编排、Pydantic 合同、和风天气/高德受控客户端、进程内缓存、有限重试、熔断、受控降级、文档处理基础链路和前端 Markdown 净化；
- 当前边界：只读建议，不执行预订、支付、库存确认或交易；
- 规划中：single-flight、统一请求级 deadline、缓存淘汰、认证、限流、租户隔离、集中式密钥管理、审计和监控告警等。

不得在页面中出现真实密钥、Token、Cookie、Authorization、未脱敏供应商响应、虚构的实时指标或虚构的可用性承诺。

## 6. 验证标准

完成后应满足：

- HTML 文件可由浏览器直接打开，不依赖网络；
- 页面包含上述六类核心图示和完整文字说明；
- 图中模块名称与当前项目文件/README 一致；
- 浅色、深色和窄屏布局均可阅读；
- HTML 内不存在外部脚本、外部样式表或网络请求；
- `git diff --check` 通过；
- 对新增 HTML 执行基础结构检查，确认标题、章节锚点、SVG、脚本和关键术语存在；
- 不修改用户已有的其他工作树变更。
