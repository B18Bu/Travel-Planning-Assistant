# 模拟界面企业级 UI 重构设计

**日期：** 2026-08-20  
**范围：** `layout-prototype.html` 的视觉结构、交互反馈和动效；不改变既有演示数据、任务模型或业务流程。

## 1. 目标与成功标准

将首页原本并列的“自定义搜索”和“完整规划”卡片合并为单个企业级主导航窗格，同时保留左侧导航、任务结果、反馈、设置和数据看板。

成功标准：

1. 首页呈现浅色、克制、专业的企业级视觉风格。
2. 主导航窗格左右分区：左侧为出行规划，右侧依次为数字人占位和自定义搜索；中间使用 `1px dashed #D1D5DB` 垂直分隔。
3. 左侧出行规划在输入区上方显示多图自动切换窗口，并在输入区下方放置现有快捷地区。
4. 数字人仅为可替换的视觉占位，不接入模型或新增对话逻辑。
5. 查询记录改为可交互管理的键组，且不改变现有的任务切换、单条删除和清空行为。
6. 视图、数字、图表与图片切换均无硬切，并尊重减少动态效果偏好。

## 2. 页面结构

### 2.1 全局框架

保留现有结构：前导页、顶部品牌栏、左侧导航、右侧主内容、设置弹窗和删除确认弹窗。

- 基础背景使用 `#F8FAFC` / `#F3F4F6`。
- 容器使用白色表面、`#E5E7EB` 细边框和低强度柔和阴影。
- 字体继续使用现有中文无衬线字体栈。
- 主色统一为企业蓝，主标题“开始一段值得期待的旅程”使用 `#2563EB`。

### 2.2 前导页

前导页保留产品名、副标题、三项能力、演示标记和“开始体验”入口，升级为企业级左右平衡启动页。

- 顶部保留带地球标识的品牌栏与“界面原型 · 演示数据”标记；正文左侧不再展示独立地球图标。
- 桌面端正文使用无可见分隔线的双栏布局：左侧约占 `46%`，承载蓝色主标题“把下一段旅程交给智能规划”、现有副标题、开始体验按钮和三项能力窗格；右侧约占 `54%`，作为抽象地平线航迹主视觉。
- 三项能力窗格完整保留“完整规划 / 目的地攻略 / 数据看板”及各自的现有说明文字。
- 右侧主视觉由柔和蓝色光晕、双层虚线弧线、起点/终点节点、`FROM · START`、`TO · DISCOVER` 和底部 `TRAVEL · PLAN · DISCOVER` 组成；这是纯 CSS 装饰，不增加功能、数据或素材依赖。
- 入场时左侧标题、副标题和开始体验按钮依次上浮渐现；三项能力窗格按顺序渐现；右侧航迹轻微渐入，节点采用低干扰呼吸效果。
- `prefers-reduced-motion: reduce` 下所有前导页动画关闭；窄屏下隐藏右侧装饰区，左侧内容单列完整显示。
- 点击“开始体验”仍调用既有 `startExperience()`，前导页淡出后主界面继续依次渐现。

### 2.3 左侧导航与查询记录

保留“新建任务”“查询记录”“数据看板”“知识库信息”“最近索引”和“设置”内容与入口。

查询记录改为白色边框管理容器：

- 头部显示“查询记录”、记录数量、收起/展开按钮和“清空”入口。
- 每条记录是整行可点击的交互键，点击调用既有任务选择逻辑。
- 当前选中任务使用浅蓝背景和蓝色边框。
- 每条记录继续显示任务类型图标、标题和摘要；悬停显示单条删除按钮，仍使用既有确认弹窗。
- 底部显示“按时间排序”和“管理记录 →”。后者仅是视觉预留，不新增独立管理视图、数据字段或业务逻辑。

### 2.4 首页统一主导航窗格

首页欢迎区下方改为一张主导航容器，取消原有两张模式卡片的并列布局。

**左侧：出行规划**

1. 保留“始发地”“目的地”和“生成方案”输入/提交行为及原有元素 ID。
2. 输入区上方为旅行图片展示窗口。图片来源为后续传入的图片列表；本次重构只提供前端数组/占位结构，不内置真实素材。
3. 输入区和主按钮下方放置“快捷地区”及成都、三亚、西安、桂林按钮，保持既有快捷查询行为。

**中部：区域分隔**

- 桌面端使用 `border-right: 1px dashed #D1D5DB` 或等效伪元素形成垂直灰色虚线。
- 窄屏转为水平虚线，确保移动端阅读顺序合理。

**右侧：数字人和自定义搜索**

1. 顶部放置数字人 / AI Agent 占位容器，包含占位头像、循环波形和清晰的 `VISUAL ANCHOR · PLACEHOLDER` 注释。
2. 容器为未来数字人模型的内部展示层预留稳定选择器/容器；不新增真实模型请求、聊天输入或消息状态。
3. 数字人下方放置现有“自定义搜索”输入和“查攻略”按钮，保留原有搜索行为与 Enter 键处理。

## 3. 动效与可访问性

### 3.1 图片展示窗口

- 从未来的图片列表中读取多张图片并按顺序自动切换。
- 单图展示约 4 秒；使用交叉淡入淡出和轻微缩放，禁止硬切。
- 显示低干扰进度点，不添加点击翻页、远程加载或新的业务状态。
- `prefers-reduced-motion: reduce` 下停止自动切换和缩放，仅展示首张图片。

### 3.2 前导页、页面与数据动效

- 前导页遵循 2.2 节的分段入场顺序；右侧航迹不应包含硬切或高频动画。
- 复用或优化既有视图进入的淡入 + 轻微上移过渡。
- 数据看板统计数字继续使用 `requestAnimationFrame` 计数动画。
- 进度条使用从 0 到目标宽度的缓动延展；数据行继续按序渐现。
- 所有动效均在减少动态效果偏好下关闭或显著降级。

## 4. 响应式规则

- `max-width: 900px`：主导航容器变为单列；左右虚线分隔改为水平分隔；左侧导航沿用现有横向/折行策略。
- `max-width: 640px`：收紧主内容 padding；始发地与目的地可堆叠；快捷地区允许换行；表格和图表内容不可撑出视口。
- 输入、按钮保持最小可点击高度与清晰的主次对比：主按钮为企业蓝实心，次级操作为白底描边/幽灵样式。

## 5. 实施边界

**保留且不改变：** 演示任务数据、任务创建/处理阶段、结果内容、赞踩逻辑、删除确认、设置本地存储、数据看板指标和表格内容。

**明确不做：** 数字人模型接入、聊天功能、图片上传 UI、真实轮播数据服务、独立查询记录管理页面、新数据字段或后端接口改造。

## 6. 验证方案

1. 在浏览器打开 `layout-prototype.html`，确认前导页、首页、任务结果、数据看板和设置均可访问；前导页左侧内容、三项能力窗格和右侧航迹均符合 2.2 节布局。
2. 验证出行规划、自定义搜索、快捷地区、任务选择、赞踩、单条删除和清空记录与重构前一致。
3. 验证图片窗口多图交叉切换及“减少动态效果”下降级表现。
4. 验证桌面端垂直虚线与移动端单列水平虚线。
5. 检查 1440px、900px、640px 宽度下无水平溢出，主按钮与输入框可操作。
