# 飞猪门票查询设计

**日期：** 2026-08-25  
**状态：** 待用户审阅  
**范围：** 将工作台原“车票查询”功能调整为“门票查询”，基于飞猪门票商品管理 API 查询已接入景点的门票商品、指定日期价格/库存和入园规则；不创建订单、不支付、不提供预订按钮。

## 1. 背景与结论

飞猪官方 API 目录中的火车票接口目前主要覆盖代理商订单、出票、退票、改签、候补和占座流程，未发现可直接支持普通用户“出发地 + 目的地 + 日期 → 车次/票价/余票”的公开车次查询接口。因此，项目将左侧“车票查询”调整为“门票查询”。

官方门票 API 能力更匹配景区商品查询：

- [度假－商品管理 API 类目](https://open.alitrip.com/docs/api_list.htm?cid=20751)；
- [`taobao.alitrip.travel.baseinfo.scenics.get`](https://open.alitrip.com/docs/api.htm?apiId=25781)：按城市和景点关键词查询景点及其门票套餐；
- [`taobao.alitrip.travel.item.single.query`](https://open.alitrip.com/docs/api.htm?apiId=25767)：按商品 ID 查询商品、票种、日期价格/库存和商品规则。

这两个接口的官方定位是度假/门票商品发布和查询辅助，均需要授权。它们能支撑已接入商品的查询，但不等同于全网景点搜索，也不提供订单创建、支付或核销。

这两个 API 需要应用授权和卖家/商品范围确认。`baseinfo.scenics.get` 返回已接入的景点及 `spuList`，不是全网景点搜索；`item.single.query` 的官方请求字段不包含游客人数，因此游客人数只在本地校验和结果上下文中使用，不发送给飞猪。

## 2. 产品范围

### 2.1 查询条件

- `scenic_keyword`：景点关键词，去除首尾空白，长度 1—100；
- `entry_date`：入园日期，不早于服务端当前日期；
- `visitor_count`：游客人数，整数 1—20，仅用于本地校验和结果上下文展示。

用户不需要输入 `ali_scenic_id`、`item_id` 或商家编码。后端负责将景点关键词匹配到已授权景点和门票商品。

### 2.2 结果展示

一个景点匹配多个商品时，全部展示，不只保留最低价。每个商品卡片可展示以下已授权字段：

- 商品名称、票种、场次、区域；
- 飞猪商品图片（仅取得图片展示许可后启用）；
- 指定入园日期价格、币种和官方库存值；
- 门票有效期；
- 入园地址、换票方式、发码方式；
- 退改说明；
- 游客信息要求和限购规则；
- 飞猪来源、查询时间和实时状态。

价格和库存每次主动查询都重新请求飞猪，不缓存。页面必须提示：价格和库存仅代表查询时刻，不代表最终可售、锁库存或预订成功。

### 2.3 明确不包含

- 预订、购买、订单创建、支付、退款、改签、核销；
- 预订按钮或禁用预订按钮；
- 飞猪商品链接跳转，除非后续单独确认官方跳转许可；
- 游客姓名、身份证、手机号、护照等身份信息收集；
- 无结果时调用其他数据源或模型推荐补全；
- 将游客人数传给未声明该字段的飞猪接口。

页面固定提示：

> 本系统仅提供门票信息查询，请通过飞猪官方渠道完成购买。本页面不收集游客身份信息，不创建订单或处理支付。

## 3. 系统架构与数据流

```text
前端“门票查询”
  │ 景点关键词、入园日期、游客人数
  ▼
POST /api/fliggy/tickets/search
  │ 服务端校验 + request_id
  ▼
FliggyTicketService
  ├─ taobao.alitrip.travel.baseinfo.scenics.get
  │    景点关键词 → 景点及门票套餐 SPU
  └─ taobao.alitrip.travel.item.single.query
       商品 ID → 票种、指定日期价格/库存和商品规则
  ▼
白名单字段映射 + 状态归一化
  ▼
前端商品列表
```

服务端必须固定 TOP Router 的 HTTPS 地址、API 方法、`v=2.0`、JSON 格式、签名和授权配置。公共参数包括 `method`、`app_key`、`sign_method`、`sign`、`timestamp`、`v`；具体 `session`、渠道和卖家资质以应用授权为准。真实密钥、签名和 session 只存在后端受控配置中。

## 4. API 合同

### 4.1 查询接口

`POST /api/fliggy/tickets/search`

请求：

```json
{
  "scenic_keyword": "西湖",
  "entry_date": "2026-09-01",
  "visitor_count": 2
}
```

响应的固定元数据：

```json
{
  "source_name": "飞猪",
  "retrieved_at": "2026-08-25T10:00:00+08:00",
  "data_status": "realtime",
  "scenic_keyword": "西湖",
  "visitor_count": 2,
  "tickets": [],
  "warnings": []
}
```

后端只返回白名单领域字段，不透传飞猪原始响应。建议的商品领域字段：

```json
{
  "item_id": "56823636723",
  "item_name": "西湖大门票",
  "image_urls": [],
  "ticket_type": "成人票",
  "entry_date": "2026-09-01",
  "price_amount": 1234,
  "currency": "CNY",
  "price_unit": "分",
  "stock": 12,
  "stock_status": "available",
  "entry_type": "二维码直接入园",
  "entry_address": "景区入口",
  "refund_description": "按规则退改",
  "visitor_requirement": "需要姓名和身份证",
  "purchase_limit": "每日限购 1 张"
}
```

具体字段必须同时满足：飞猪返回、书面允许展示、已定义类型/单位/枚举，并且不包含订单、支付或不必要个人信息。

### 4.2 状态与错误

| 场景 | HTTP 状态 | 前端行为 |
| --- | ---: | --- |
| 服务未配置或功能关闭 | 503 | 显示“飞猪门票查询服务尚未配置”，按钮禁用。 |
| 参数不合规 | 422 | 显示中文校验提示。 |
| 未找到已接入景点/商品 | 200 | 显示“未找到已接入的门票商品，请调整关键词后重试”。 |
| 单个商品详情失败 | 200，`degraded` | 其他商品继续展示，失败商品标记详情暂不可用。 |
| 所有商品详情失败 | 503 | 清空结果，显示实时查询暂不可用。 |
| 超时、`429`、`5xx` 或鉴权失败 | 503 | 清空结果，提供重试和官方核验提示。 |
| 价格缺失 | 200 | 显示“价格信息暂不可用”。 |
| `stock = 0` | 200 | 显示“库存为 0”。 |
| 库存缺失或异常 | 200 | 显示“库存信息暂不可用”。 |

异常响应不得回显飞猪原始响应、`session`、签名、密钥、Cookie、内部 URL 或堆栈。

## 5. 隐私与安全

首次查询前显示会话级同意说明：

> 本次查询将向飞猪发送景点关键词、入园日期及必要查询参数。游客人数仅用于本页面校验和结果展示，不会发送给飞猪。本系统不收集姓名、身份证、手机号或护照信息，也不代为下单和支付。是否同意？

- 用户拒绝或关闭弹窗时不发送查询请求；
- 同意状态只保存在当前浏览器会话；
- 浏览器存储不可用时，每次查询重新确认；
- 不使用 `localStorage`，不在后端持久化游客信息、查询条件或结果；
- 价格和库存不缓存；
- 日志只保留脱敏 `request_id`、功能类型、错误分类、耗时和上游状态；
- 图片 URL 只有取得展示许可后才能渲染，加载失败时隐藏图片而不伪造占位图；
- 供应商文本使用 `textContent` 等安全 DOM API，不把原始 HTML 写入页面。

## 6. 降级与边界

1. 景点无商品时不调用商品详情和规则接口，直接返回空列表；
2. 多个商品中单个详情失败时继续处理其他商品，并标记顶层 `degraded`；
3. 价格或库存缺失不转换为默认值，不把缺失库存显示成有库存；
4. 任何上游失败都不使用旧结果、缓存结果、知识库或模型输出替代；
5. 游客人数不参与飞猪请求，不解释为价格或库存计算条件；
6. “库存数量”只表述为查询时飞猪返回值，不表述为最终可售保证。

## 7. 测试与验收

### 7.1 后端

- 请求字段、日期和人数边界校验；
- 游客人数不进入飞猪请求参数；
- `baseinfo.scenics.get` 返回的多个 `spu` 全部保留；
- `item.single.query` 只选择与 `entry_date` 匹配的 `prices`；
- 价格单位精确到分，并明确币种；
- `stock = 0`、库存缺失和库存异常分别处理；
- `item.single.query` 返回的预订规则、景点信息和游客要求按白名单映射；
- 景点无商品时跳过后续调用；
- 单商品失败与全部失败分别降级；
- 超时、`429`、`5xx`、鉴权失败不泄露上游数据；
- 查询不读写价格/库存缓存；
- 不产生订单、支付或外部写操作。

### 7.2 前端

- “车票查询”替换为“门票查询”，“酒店查询”保持不变；
- 未配置时入口可见、按钮禁用、无模拟数据；
- 同意前不请求，拒绝后不请求；
- 结果包含多个商品卡片；
- 精确价格、库存 0、缺失库存和失败状态按规则展示；
- 查询失败清空旧结果；
- 不出现预订、购买、支付或游客身份输入框；
- 门票图片仅在授权开关开启后展示；
- 窄屏无横向溢出。

## 8. 启用前置条件

真实门票查询启用前必须完成：

1. 飞猪应用授权、卖家/渠道范围与 `session` 获取方式确认；
2. `baseinfo.scenics.get`、`item.single.query` 的正式字段和错误码登记；
3. 价格、库存、图片、规则和游客信息要求的书面展示许可；
4. 正式环境/测试环境、限流、超时、重试和缓存限制确认；
5. 真实凭据只配置在后端受控环境；
6. 完成沙箱契约测试、安全测试和发布评审；
7. 服务端开关可关闭真实调用并回到“服务筹备中”状态。

在上述条件完成前，页面可以实现并展示筹备态，但不得请求飞猪或展示模拟实时交易数据。
