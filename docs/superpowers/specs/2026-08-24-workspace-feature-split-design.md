# 工作台行程规划与攻略查询拆分设计

**日期：** 2026-08-24  
**状态：** 已确认，待审查书面规格  
**范围：** 仅调整前端工作台的导航与功能区布局；不修改欢迎页文案、其他功能模块、后端接口或检索/规划业务逻辑。

---

## 1. 目标

将当前工作台内并列的两种功能拆分为独立的前端内部视图，降低单页信息密度并使功能入口更清晰：

1. 在左侧导航新增“行程规划”和“攻略查询”入口；
2. 行程规划页采用左侧流动图片、右侧行程填写表单的双栏布局；
3. 攻略查询页采用左侧数字人讲解占位、右侧自定义搜索及结果的双栏布局；
4. 表单提交后继续进入既有方案结果页；攻略查询继续使用既有检索结果卡片与来源信息；
5. 保持欢迎页为默认首页，保留其已有欢迎语、标题、说明文案，不再在首页显示原先的双栏操作区。

## 2. 非目标与严格边界

以下内容不在本次范围内：

- 不新增 URL 路由、路由库或改变部署方式；继续使用 `showView()` 的前端内部视图切换。
- 不改变欢迎页的欢迎语、标题、说明文案，亦不在欢迎页新增跳转卡片或空白提示区。
- 不改动数据看板、文档库、查询记录、设置、既有方案结果页及其交互。
- 不改动后端接口、RAG 检索、文档库、行程生成、多 Agent 或大模型调用逻辑。
- 不接入真实数字人能力；数字人区域继续为现有视觉占位。

## 3. 信息架构与视图流转

```text
默认首页（home）
├─ 保留现有欢迎内容
└─ 不显示行程表单、攻略搜索或其展示区

左侧导航
├─ 行程规划（plan） → 行程规划双栏页 → 既有任务结果页（task）
├─ 攻略查询（guide） → 攻略查询双栏页（结果在当前页）
├─ 数据看板（dashboard）
├─ 文档库（library）
├─ 查询记录（既有历史列表）
└─ 设置
```

首次进入、点击品牌、清空任务或删除当前记录后，均保持现有返回默认首页的语义。

## 4. 页面设计

### 4.1 行程规划视图

- 左栏复用现有流动图片轮播与自动切换逻辑。
- 右栏复用原有始发地、目的地、出行日期、人数、天数、预算、偏好与状态/错误提示。
- 表单仍由现有提交逻辑和接口处理；成功后仍展示既有方案结果页，并按既有规则加入左侧查询记录。

### 4.2 攻略查询视图

- 左栏复用数字人讲解占位卡片，不改变其占位性质和现有文案。
- 右栏复用自定义搜索框、检索范围说明与结果区。
- 请求仍调用 `/api/knowledge-search`；保留当前来源展示、查询记录、完整回答入口与错误/空结果行为。
- 搜索响应仅在攻略查询视图仍激活时渲染，避免用户切换其他视图后出现过期结果。

### 4.3 响应式行为

- 桌面端：视觉展示区在左，操作区在右。
- 窄屏端：两个功能页切换为上下排列，视觉区在上，操作区在下。
- 页面主体不得产生横向滚动，输入项应维持可操作尺寸。

## 5. 实现边界

仅修改以下文件：

| 文件 | 变更职责 |
| --- | --- |
| `frontend/index.html` | 新增两项侧栏导航与两个独立视图；首页保留欢迎内容并移除旧双栏功能区；移动既有功能 DOM。 |
| `frontend/app.js` | 将导航接入 `showView()`；保持既有表单、搜索、轮播、查询记录与结果跳转逻辑；将搜索视图激活判断改为攻略查询视图。 |
| `frontend/styles.css` | 新增复用式功能双栏与窄屏堆叠样式；移除只服务于首页旧双栏布局的规则；保留既有组件视觉样式。 |

## 6. 验收标准

1. 默认首页仍显示原有欢迎语、标题和说明，不显示原来的双栏操作区。
2. 左侧导航显示“行程规划”“攻略查询”，点击可切换至对应独立视图。
3. 行程规划页为“左流动图片、右行程表单”；成功提交后仍进入现有方案结果页。
4. 攻略查询页为“左数字人占位、右搜索与结果”；检索结果仍含可追溯来源。
5. 数据看板、文档库、查询记录、设置、欢迎页文案与既有结果页不发生行为或视觉改动。
6. 窄屏下两个功能页上下堆叠，且无横向溢出。
7. 仅有 `frontend/index.html`、`frontend/app.js`、`frontend/styles.css` 发生产品实现改动，不更改后端合同。
