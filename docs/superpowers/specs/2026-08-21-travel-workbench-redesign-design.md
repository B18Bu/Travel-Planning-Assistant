# 旅行规划工作台重构设计

**日期：** 2026-08-21
**状态：** 待书面规格审查
**范围：** 以 `layout-prototype.html` 的视觉语言重构当前同源旅行规划前端；保留真实 MVP API、表单、状态与安全展示，不实现原型中未落地的业务能力。

---

## 1. 目标与范围

### 1.1 目标

当前前端已能提交旅行规划请求并安全展示结果，但页面是简化表单，未体现项目原型中的品牌前导页、企业工作台和导航层级。

本次重构将当前真实功能置入原型式工作台：用户先在前导页点击「开始体验」，进入包含品牌栏、侧边导航、旅行表单和双栏结果区的主工作区。结果仍由 `/api/travel-plans` 返回，页面仍使用本地 `marked` 和 DOMPurify 安全展示。

### 1.2 本次包含

- 原型式前导页与旅行航迹装饰；
- 顶部品牌栏、MVP 标识和侧边导航；
- 真实旅行规划表单与 API 提交；
- 原型式任务状态、表单卡片和结果工作区；
- 真实 Markdown 行程、待核验事项、来源与降级说明双栏展示；
- 前端状态：初始、提交中、成功、`degraded`、`failed` 和 API 错误；
- 响应式布局与键盘可用性；
- 前端静态资源和安全回归测试。

### 1.3 明确不包含

下列原型能力保持为只读占位或不显示，不新增 API、存储、请求或模拟数据：

- 查询历史和本地持久化；
- 知识库检索、文档索引和地区攻略；
- 数据看板、反馈/赞踩和统计数据；
- 数字人、模型配置和设置弹窗；
- 用户账户、认证、租户和管理后台。

占位项必须明确说明「当前 MVP 未启用」，不得让用户误以为已经可用。

## 2. 信息架构与视图状态

```text
前导页 intro
  └─ 开始体验
       └─ 工作台 workspace
            ├─ 顶部品牌栏
            ├─ 侧边导航
            │    ├─ 新建旅行规划（可用）
            │    └─ 能力概览（只读 MVP 占位）
            └─ 主工作区
                 ├─ 表单卡片
                 └─ 结果视图
                      ├─ Markdown 行程正文
                      └─ 待核验 / 来源 / 降级侧栏
```

前导页默认可见，工作台默认隐藏。点击「开始体验」后切换至工作台，并将键盘焦点移动到工作区标题或出发地输入框。点击侧边栏「新建旅行规划」清空结果、恢复表单视图，不发送网络请求。

页面不使用前端路由、查询历史或浏览器存储。刷新页面回到前导页。

## 3. 视觉与交互

### 3.1 前导页

沿用原型的浅色企业工作台气质：

- 左侧：产品名称、主标题、说明、开始体验按钮、真实能力说明；
- 右侧：纯 CSS/SVG 的旅行弧线和起终点节点，不加载远程图片；
- 前导页文字只描述当前真实 MVP 能力：结构化规划、来源可追溯、降级核验；
- 不展示「知识库检索」「数据看板」等未实现能力的可用承诺。

### 3.2 工作台

- 顶部栏：产品名、MVP 标识；
- 侧边栏：新建旅行规划按钮、当前功能说明、未启用能力的静态说明；
- 主区上方：欢迎语与当前功能说明；
- 表单卡片：保留出发地、目的地、日期、人数、天数、预算、偏好；
- 结果页：桌面双栏，正文约占 2/3，右侧元数据约占 1/3；
- 小于等于 `768px`：侧边栏成为工作区上方的紧凑导航，结果改为单栏。

不采用原型中的假数据图表、历史记录计数、反馈按钮或配置输入，以免制造不可用功能的错觉。

## 4. 真实 API 与状态呈现

表单继续以同源相对路径 `POST /api/travel-plans` 请求真实后端：

- 本地验证：地点非空、出行日期不早于今天、人数 1—20、天数 1—14、预算 0—200000；
- 发送：按钮禁用、展示「正在生成旅行规划」、隐藏旧结果；
- HTTP 非 2xx：安全读取受控 `detail`，字符串直接文本展示；对象/数组显示「请求参数不符合要求」；
- `status=success`：显示「规划已生成」；
- `status=degraded`：显示「规划已生成，部分信息需要核验」；
- `status=failed`：显示「规划生成失败，页面内容仅供核验」，仍展示服务端返回的 Markdown、来源、警告和失败说明；
- 所有错误均通过 `textContent` 进入状态或错误区域，不使用 `innerHTML`。

`itinerary` 是 API 结构化合同，不在页面输出 JSON 或调试文本。

---

## 5. 安全展示

现有安全边界必须保持：

1. 仅 `documentData.markdown` 可进入 `innerHTML`；
2. Markdown 固定走 `marked.parse` 后再走 DOMPurify；
3. DOMPurify 禁止 `script`、`style`、`svg`、`math` 与事件属性；
4. 来源、警告、降级说明、失败说明、表单错误都使用 `createElement`、`textContent` 和 `replaceChildren`；
5. 所有第三方运行时文件仍在 `frontend/vendor/` 本地加载，不使用 CDN；
6. 页面不得包含 API Key、后端基础 URL、供应商原始响应、JSON 源码或内部异常。

## 6. 文件与测试影响

### 修改文件

- `frontend/index.html`：替换为前导页 + 工作台结构；
- `frontend/styles.css`：采用原型视觉令牌、响应式侧边栏和结果布局；
- `frontend/app.js`：增加视图切换、新建规划、焦点管理和工作台状态；保留安全请求与渲染；
- `backend/tests/test_frontend_assets.py`：扩展原型工作台静态结构、未启用占位文案、前导页和安全展示回归。

### 不修改文件

- `backend/app/models/travel.py`；
- 所有外部服务、Agent、编排和 API 合同；
- `frontend/vendor/marked.min.js`、`frontend/vendor/purify.min.js`、`THIRD_PARTY_NOTICES.md`，除非哈希验证发现文件损坏。

### 验收

- 根路径默认显示前导页；
- 「开始体验」显示真实旅行表单；
- 「新建旅行规划」可回到干净表单，不请求 API；
- 表单提交、成功/降级/失败和非 2xx 错误可见；
- 结果不展示 JSON 源码；
- Markdown 和元数据安全边界不回退；
- 未启用能力不触发 API；
- `backend/tests`、前端静态测试、`node --check frontend/app.js` 和 `git diff --check` 均通过。

## 7. 规格自检

- 保留真实 MVP 功能，不新增后端能力或假数据；
- 原型未实现功能只有清晰占位，不可交互；
- 页面安全边界沿用现有本地依赖与纯文本元数据渲染；
- 视觉重构不改变旅行数据合同、API 请求路径或响应形状；
- 响应式断点与结果双栏规则明确；
- 不包含 TODO、待定或模糊的实现占位。
