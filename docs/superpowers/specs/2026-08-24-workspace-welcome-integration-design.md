# 工作台欢迎语并入功能页设计

**日期：** 2026-08-24  
**状态：** 已实现，待浏览器回归验证
**范围：** 仅将当前欢迎语区并入“行程规划”和“攻略查询”两个功能页，并删除无交互内容的内部首页视图；不改动其他工作台模块、业务交互或后端接口。

---

## 1. 目标

移除工作台内只承载欢迎语、没有可操作内容的空白首页，使用户进入工作台后直接进入行程规划；同时在两个核心功能页顶部保留同一套欢迎内容与视觉表达。

欢迎内容保持以下文案不变：

```text
企业级智能文旅工作台
欢迎使用智能文旅策划助手
统一入口承载出行规划、数字人服务与目的地知识检索
```

## 2. 页面与导航行为

```text
进入工作台 / 点击品牌 / 清空记录 / 删除当前记录
└─ 行程规划（plan）
   ├─ 欢迎语区
   ├─ 行程规划标题与说明
   └─ 左侧流动图片 + 右侧行程表单

攻略查询（guide）
├─ 欢迎语区
├─ 攻略查询标题与说明
└─ 左侧数字人占位 + 右侧搜索与检索结果
```

- 删除 `view-home`，不保留新的首页导航项或空白占位。
- 左侧导航保持现有“行程规划”“攻略查询”“数据看板”“文档库”等入口；无需增加“首页”。
- 顶部品牌按钮不再进入已删除的首页，改为显示“行程规划”。
- “清空查询记录”和删除当前任务后的回退目标同样改为“行程规划”。
- “＋ 新建任务”已使用行程规划页，保持该行为不变。

## 3. 组件与视觉规则

### 3.1 欢迎语区

- 每个功能页各自拥有一份欢迎语 DOM，避免跨视图移动节点或产生异步切换问题。
- 复用既有 `.home-welcome`、`.home-eyebrow`、`.home-welcome h2`、`.home-welcome p` 的字体、颜色和文案；只新增功能页内的间距控制。
- 欢迎语区位于功能页标题和双栏功能区之前。
- 不为欢迎语区新增交互、跳转按钮或卡片。

### 3.2 视图布局

- 行程规划仍为：欢迎语区 → 规划标题与说明 → 左流动图片、右表单。
- 攻略查询仍为：欢迎语区 → 查询标题与说明 → 左数字人占位、右搜索及结果。
- 既有桌面双栏、窄屏纵向堆叠、攻略结果区域滚动约束均保持不变。
- 数据看板、文档库、查询记录、设置、方案结果视图不使用欢迎语区，视觉与交互均不改动。

## 4. 实现边界

| 文件 | 变更职责 |
| --- | --- |
| `frontend/index.html` | 删除 `view-home`；在 `view-plan` 与 `view-guide` 中各插入既有欢迎语区内容。 |
| `frontend/app.js` | 删除仅服务 `view-home` 的高度适配；将品牌返回、清空记录、删除当前任务后的回退目标统一改为 `plan`。 |
| `frontend/styles.css` | 删除 `#view-home` 专用规则；为功能页内欢迎语区设置受控间距，保留既有欢迎文本视觉规则和功能页双栏规则。 |

不修改后端、接口、RAG 搜索、行程规划、查询记录数据模型或其他页面。

## 5. 验收标准

1. 启动并进入工作台后，默认显示“行程规划”视图，不存在 `view-home`。
2. 行程规划与攻略查询均显示完整且文案一致的欢迎语区。
3. 两个功能页中的欢迎语区视觉字体、颜色与现有欢迎语一致。
4. 点击顶部品牌、清空查询记录、删除当前任务后，均显示行程规划页。
5. 行程规划提交、攻略查询、流动图片、数字人占位、桌面双栏、窄屏纵向堆叠保持原行为。
6. 数据看板、文档库、查询记录、设置和任务结果页无结构、行为或视觉改动。
7. 仅修改 `frontend/index.html`、`frontend/app.js`、`frontend/styles.css`。
