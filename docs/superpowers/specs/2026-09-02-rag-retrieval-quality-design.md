# RAG 检索质量与提示优化设计

## 目标

提高知识库检索结果的相关性与可读性，并让用户能区分无资料、无匹配和检索服务异常。

## 范围

- 在现有城市/省域识别基础上，使用本地旅游意图词识别“亲子”“室内”“慢游”等查询修饰词。
- 保持向量检索、关键词检索、RRF 融合和地区硬过滤不变。
- 对融合结果按规范化片段内容做精确去重，避免相同文本块重复返回。
- 为无结果返回受控原因：没有已处理文档、目标地区没有资料、没有相关片段。
- 前端针对每种无结果原因提供具体操作建议；检索引擎异常继续使用不泄露内部信息的重试提示。

## 方案

关键词检索新增固定的旅游修饰词词典，命中的修饰词作为独立计分项参与关键词排序；不使用模型进行查询改写。RRF 融合后保留首次出现的每个规范化片段内容，直至达到结果上限。规范化仅折叠空白和大小写，不做模糊相似度判断，避免删除事实不同的相近段落。

`KnowledgeSearchResponse` 增加可选的空结果原因枚举。当 `results` 为空时，API 根据已处理文档集合和查询地区生成原因；当 `results` 非空时该字段为 `null`。前端只根据受控枚举显示提示，不拼接服务端异常或原始响应。

## 空结果与异常提示

| 场景 | 原因代码 | 用户提示 |
| --- | --- | --- |
| 没有已处理文档 | `no_ready_documents` | 暂无可检索资料，请先上传文档并等待处理完成。 |
| 查询地区没有资料 | `no_region_documents` | 目标地区暂无已处理资料，请更换地区或上传相关攻略。 |
| 有资料但无相关片段 | `no_matching_chunks` | 未找到相关内容，请尝试更具体的景点、玩法或主题关键词。 |
| 检索引擎异常 | 不进入响应模型 | 检索引擎暂时不可用，请稍后重试。 |

## 验收与测试

- “成都亲子博物馆”同时识别成都、景点和亲子修饰词，并提升含“亲子”的片段排序。
- 内容仅空白差异的多个候选只返回一条；内容不同的相邻片段均可保留。
- 三种空结果场景返回准确原因代码，前端显示相应提示。
- Chroma 或嵌入失败仍返回 503，前端显示安全的重试提示，不暴露堆栈、路径、密钥或上游响应。
